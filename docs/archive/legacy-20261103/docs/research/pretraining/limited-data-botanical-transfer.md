# Limited-data SyntheticMRI: botanical versus vessel-only pretraining

## Hypothesis and locked comparison

Does leaf diversity improve complete vessel graph reconstruction when only 200 annotated vascular patches are available, under equal optimizer-update and example-processing budgets? One shared seed (364505); a promising difference will need replication. The reference full-data study favored MRI-only. These runs test a different annotation budget, and their scores must not be treated as a seed-controlled contrast with that earlier study.

A: selected 200 MRI patches for pretraining and fine-tuning. B: the identical 200 MRI patches plus 25,000 leaf training patches for pretraining, then the same 200 MRI patches for fine-tuning. No other sources. The subset is 2.00% of the actual 10,000-patch reference training population.

## Data provenance and membership

MRI root: `/lustre/fsn1/projects/rech/vnc/upz25mj/experiments/gnbm/spline_learning/scratch_comparison_10k_300ep/spline`. The MRI `patient_id` grouping was checked for every patch: no subject occurs in more than one split. The 200 selected patches cover 62 training volumes. No validation or test MRI enters training. Selection uses the existing seeded-random ranking rather than graph quality or outcomes.

## Stages, initialization and losses

Reuse the documented full-data protocol: graph-only pretraining followed by joint detector training with a detached residual B-spline geometry branch (8 controls, local image features, spline weight 1.4739989612791453). The spline parameters are frozen during graph-only pretraining. Both fine-tuning branches initialize spline parameters identically from a fresh shared seed, and transfer their own validation-selected detector. A common immutable scratch initializer is generated by verification; both pretraining arms load it and record the same detector/spline SHA256. No previously trained weights are loaded as a scratch initializer. Reference `base_config` supplies settings only.

Domain policy: **none**. `none` disables domain adaptation in both arms and gives identical model/loss definitions. `mixed_only` retains the historical domain loss weight 1.0 only for B and therefore tests the transfer recipe with a different auxiliary objective; it is not a data-only ablation.

Same Hungarian matcher, graph losses, AdamW (LR 7e-05, weight decay 1e-4), batch 32, polynomial power 0.9, no early stopping. MRI augmentation: quarter-turn 3D rotations and Gaussian noise probability 0.35 / maximum SD 0.015; no zoom. Train BatchNorm statistics during updates; use saved statistics at evaluation. The whole detector trains in both stages; only spline gradients are detached from detector tokens/endpoints in fine-tuning.

## Fixed budgets and exposure accounting

Reference summaries establish 78,150 pretraining updates and 31,300 fine-tuning updates. Each arm uses exactly those counts. Fifty scheduler units of 1,563 updates and 100 units of 313 updates preserve the old schedule and validation cadence. Warmup is 1,563 / 313 updates. These are reference-sized scheduler units, not passes through the 200-patch dataset.

Every batch has 32 examples: 2,500,800 pretraining presentations and 1,001,600 fine-tuning presentations per arm. The reference run's partial last batches are padded by extra replacement draws (800 extra presentations across pretraining, 1,600 across fine-tuning), preserving optimizer counts while matching full batch sizes between arms.

A uses replacement draws of the 200 MRI patches. B reuses the existing weighted replacement sampler: expected 50% leaves / 50% MRI (individual MRI weight = 25000/200). Thus A has 2,500,800 MRI pretraining presentations; B expects 1,250,400 MRI and 1,250,400 leaf presentations. Fine-tuning has 1,001,600 MRI presentations in each arm. **Target exposure is not matched.** Exact realized domain totals and unique IDs are recorded from successfully optimized batches, excluding worker prefetch, in each run's `exposure.json` and checkpoints. Sampler RNG and counters survive continuations. Learning curves are `history.jsonl`, `training-losses.jsonl` and offline W&B logs.

## Evaluation and selection

Same existing 128-patch subject-disjoint validation monitor every five scheduler units; select maximum common Branch F1, then native edge F1, as before. Evaluate both final and validation-selected checkpoints on all 1,952 validation patches. Independent test (13,071 patches) uses validation-selected checkpoints only, unchanged locked thresholds, saved BatchNorm statistics and existing native/common/core evaluation. No test-driven selection.

Report native node/edge precision, recall, F1, mAP/mAR, common Branch/Curve F1, Betti component/cycle errors, SMD, predicted node/edge counts and duplicate nodes. Duplicate definition: after existing unique node matching at 2 mm, unmatched predictions within 2 mm of an already recovered GT node; reported separately from native box-based matching. Geometry is measured against extracted uncertain guides. Monitor train graph/geometry on exactly the selected 200 MRI patches, without augmentation, so training/validation divergence can be inspected.

## 21 October — retry of failed GPU smoke

Smoke1344474 timed out after a DataLoader multiprocessing resource-sharer error, `AF_UNIX path too long`. A focused standard-library Listener reproduction and a regression using the actual shell runtime setup reproduced the same failure. The regression passes after shortening JOBSCRATCH/TMPDIR to `$SCRATCH/tmp/lt-$SLURM_JOB_ID`. Runtime packages remain on SCRATCH; there is no return to node-local `/tmp` staging. Training, evaluation and CPU-check wrappers share this setup. A real multiprocessing socket is opened and closed at startup, before loading models/data, to fail immediately if the path cannot be used.

The failed chain is terminal, and no equivalent active jobs existed at audit. Retry archives the prior submission as `experiments/limited_botanical_transfer/submission-1344474.json`.
